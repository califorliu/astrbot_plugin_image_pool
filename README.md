# 角色图库（astrbot_plugin_image_pool） v1.7.0

AstrBot 插件：按分类（= tag）管理图片 —— 收录（支持多分类与引用）、随机出图、多图、指定 id、
全库随机、分类整理、**标签别名**、图片屏蔽、WebUI 可视化重分类、按引用图删除/换 tag，
外加可选的群内潜水采集（偷图）、**群级三档权限**与**保留期清理**。

## 变更记录

> 只列**用户可见**的变化；开发期的审查与验证记录不随包发布。

### v1.7.0 —— 跨插件公开入库接口

- 新增公开方法
  `ingest_files(paths, *, tag, group_id="", uploader="", source="x") -> (added, skipped)`：
  供其它插件（如 [astrbot_plugin_x_monitor](https://github.com/califorliu/astrbot_plugin_x_monitor)）
  把文件批量收入指定分类，与 `/加图` **共用同一条写入路径**，因此继承全部既有语义：
  分类自动创建（含保留字 / 折叠冲突 / 别名占用三道闸）、`(分类, sha256)` 去重、
  全局指纹黑名单、单文件大小上限。
- 修掉该接口能触发的分类命名冲突（包括含零宽字符的分类名），避免"图看着进了库、却永远解析不到"的状态。
- `/图库 别名 收编` 现在**真的能合并折叠成对分类**（如 `Hatsune` 与 `HATSUNE` 共用同一物理目录）——
  以前 `/图库 删除` 拒绝折叠冲突时给用户指的就是这条路，但它一直是死的。
- `/加图` 一张都没进时不再一律报"跳过重复或已屏蔽"：分类名被闸门拒绝也会说明原因。

### v1.6.2

- 写入与去重的加固（不含新功能）：`_db_add` **绝不覆盖已存在的文件**（写入前把 `seq` 顺延到磁盘上的空位），
  这是折叠成对分类互相覆盖的根治手段；`/删图` 删文件前先确认没有别的索引行仍指向同一物理文件；
  `/移动` 与折叠对合并时，目标文件被别的行共用就改为**复制**而不是搬移；
  写入失败回滚时只按"内容指纹仍一致"清理本次新建的文件。
- 已知残余：回滚清理是"读内容指纹 → 删文件"两步，两步之间仍有极窄的竞态窗口（真实线程下未复现）。

## 标签别名（v1.6.0）

给一个分类登记别名（大小写变体、昵称、常见错拼），指令里写别名就**归一到原分类**，
不再因为"没见过的名字"新建一个 tag。

```
/图库 别名 加 hx 初音未来        # 以后 /加图 hx、/hx、/删图 hx 3 全都落到「初音未来」
/图库 别名 加 hatsune Hatsune   # 大小写变体
/图库 别名 列表
/图库 别名 收编 初音未末 初音未来  # 打错字已经建了分类？一键并进去并登记为别名
```

| 规则 | 说明 |
| --- | --- |
| **匹配范围** | 整词精确匹配；**大小写不敏感**（Python 侧 `casefold` 算键 —— SQLite 的 `lower()` 只认 ASCII）；**不做**前缀/子串/模糊匹配 |
| **存储** | 别名不参与目录路径，只做"输入 → 正式名"的映射；目录名永远只能是正式名 |
| **索引表** | `tag_index(key PRIMARY KEY, canonical, kind, alias_text)`：**正式名与别名共用一张表**，解析永远是一次主键查询 |
| **优先级** | 运行期**正式名 > 别名**；写入期两者**互斥**（别名不许撞正式名，新建/改名不许撞别名） |
| **同一别名被多个分类声明** | 主键硬唯一 ⇒ **先到先得，后到报错**并回显占用者；要改指向用 `force`（限全局管理员） |
| **限制** | 别名必须是单个词（不含空白与 `/`）、不能是纯数字（会和图片 id 撞车）、不能是内置指令名、不能指向另一个别名（禁链式）、单分类上限 `max_aliases_per_tag` |
| **未命中** | 只给**只读建议**「你是不是想找 ×」，绝不自动改写 —— 否则同一个输入会随分类集合漂移，不可复现 |

生命周期：**改名会让别名跟随**、**删除分类会一并清掉它的别名**（迁走的是图，不是身份）。

### 顺带根治「打错字多出一个分类」

`tag_auto_create`（默认开）关掉后，指令里出现没见过的分类名不再静默新建，而是拒绝：

```
/加图 初音未末     →  ❌ 这些分类名都不可用：初音未末
                      · 「初音未末」你是不是想找「初音未来」？
                        要固定下来请发：/图库 别名 加 初音未末 初音未来
```

默认保持开启，是为了不改变既有行为；配好别名之后再关掉最稳。

### 大小写变体为什么必须走别名

`categories.name` 是 `TEXT PRIMARY KEY`（区分大小写），而 Windows/macOS 的**目录不区分大小写**。
所以 `Hatsune` 与 `hatsune` 能同时存在于数据库，却会共用同一个目录、互相污染。
启动时会扫描这类"折叠后同键"的分类并告警（不自动合并 —— 合并要改目录名，在 Windows 上还可能失败）。

## 多分类收录（v1.5.0）

`/加图 A B C` + 一条含 4 张图的引用 = **每张图分别落进 A、B、C 三个分类**（4×3=12 条记录）。
这正是「多人图」的正确表达：一张图合法地同时属于多个 tag。

- 分隔符：空白、`,`、`，`、`、`、`+`；分类名本身不能含空格。
- 上限 `max_tags_per_add`（默认 5），超出的分类被忽略并在回执里说明。
- 每张图在每个分类下各存一份文件（沿用「分类独立目录」的既有结构），
  所以磁盘占用按分类数倍增 —— 这是刻意的取舍：让每个分类可独立移动/删除而不影响其它分类。
- 兼容：单分类写法行为与文案完全不变。

### 按图片内容操作（v1.5.0）

手机上常打不出「图片 + 文字」同一条消息，所以 `/加图`、`/删图`、`/移动` 都支持**引用**。

定位依据是 **sha256**（图片内容指纹），不是 id：

| 标识 | 含义 |
| --- | --- |
| `seq`（用户看到的 id） | **分类内**的序号，即 `UNIQUE(char_name, seq)` 的那一半 |
| `sha256` | 图片内容本身；一张图可因多 tag 存在于多行 |
| `UNIQUE(char_name, sha256)` | 数据库的约束是「**同一分类内**同一张图只能一行」，跨分类不约束 |

所以：
- `/删图 分类名` + 引用 → 只删该分类下这一张。
- `/删图` + 引用（不填分类名）→ 跨所有分类删掉同内容的每一行。
- `/移动 目标` + 引用 → 把命中的行换 tag 到目标；**同一张图在别处还有记录时只移一份，其余保留**
  （不静默删掉合法的多 tag 关系，回执里会说明跳过几张）。

### 参数消歧规则

`/分类名 3` 与 `/分类名 x3` 含义不同，靠**是否带数量标记**区分：

| 写法 | 含义 |
| --- | --- |
| `3`（裸数字） | **指定 id** —— 保持既有语义 |
| `x3` / `*3` / `×3` / `3张` | **数量**（随机 3 张） |

`/发图` 没有 id 概念，裸数字直接当数量：`/发图 3` = 全库随机 3 张。

## v1.5.0：去重未分类的语义与范围

**方向**：清掉「采集落点」分类里**已存在于其它 tag** 的采集图 —— 也就是
「潜水采集额外塞进未分类的那一份」，不是删别的 tag。

**范围被锁死**：只有 `collect_namespace`（默认「未分类」）里的行会被删除，**其它 tag 一行都不动**。
理由是多人图本来就该同时挂在多个 tag 下，若对普通 tag 做「与别处重复就去掉」，会直接删掉这些
多 tag 记录。因此：

- `/图库 去重未分类`（不带参数）= 与所有现有 tag **依次比对一次**；
- 显式传分类名时，只接受采集落点本身，传普通 tag 会被拒绝并说明原因；
- 只删 `source='auto'`（采集入库）；人工 `/加图` 的重复记录一律保留，并在回执里计数（`kept_manual`）；
- 幂等，可反复执行。

## v1.3.0 修复：指令消息不再被误采集

**现象**：群里发 `/加图 初音未来` + 图片，图片除了进「初音未来」，还被同时塞进「未分类」。

**根因**：不是白名单/静默配置的问题。`/加图` 与被动采集是**同一条消息上的两个 handler**——
`add_image` 按指令落进正确分类，`passive_collect` 因为只排除「被 @ 的消息」
（`_woken_by_at`），对**斜杠指令不做排除**，于是又按 `collect_namespace` 落了一份。
两个分类不同名，所以 `(char_name, sha256)` 的去重拦不住，形成一份图两个分类。

**修复**：新增 `collect_skip_commands`（默认开）。被动采集现在会跳过「发给机器人的消息」：

1. 命中 `@filter.command` 指令的消息 —— 用 AstrBot 的 `handlers_parsed_params` 标记识别
   （这也是 AstrBot 内置群聊上下文插件用来「跳过指令消息」的同一机制）；
2. 原始文本以唤醒前缀开头的消息（斜杠域），例如 `/随便聊聊` 这类会交给 LLM 的消息。

**存量数据修复**：`/图库 去重未分类`，只删除 `source='auto'` 且同一 sha256 已存在于别的分类的记录，
人工 `/加图` 收录的一律不动，可反复执行（幂等）。

## 保留期与容量清理（v1.3.0）

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `retention_days` | `0`（关） | 采集入库的图片保留 N 天后自动删除 |
| `max_pool_mb` | `0`（关） | 图库容量上限（MB），超出按**最旧优先**淘汰 |
| `retention_source` | `auto` | `auto`=只清采集入库的；`all`=人工收录的也清（危险） |
| `retention_exempt` | `[]` | 永久豁免清理的分类名 |
| `retention_sweep_hours` | `6` | 自动清理的检查间隔 |

安全设计：**默认只清 `source='auto'`**，人工 `/加图` 收录的图不受 TTL 影响；
想长期保留的采集图可以搬进 `retention_exempt` 里的分类。

触发方式是**惰性**的：清理挂在被动监听上按间隔节流检查，不启后台常驻任务
（避免插件重载留下野任务）。也可以随时 `/图库 清理` 手动跑一次。

## 配置作用与联动关系

### 采集相关

| 配置 | 作用 | 联动 |
| --- | --- | --- |
| `auto_collect` | 采集**总开关** | 关掉则完全不采集（但保留期清理仍会跑） |
| `collect_groups` | 哪些群采集（留空=所有群） | 填了就同时把该群标记为「偷图群」→ 触发自动静默 |
| `collect_namespace` | 采集落到哪个**分类** | 与 `default_namespace` 无关 |
| `collect_skip_commands` | 跳过指令/斜杠域消息 | 关掉会重现 v1.3.0 修的误归类 bug |
| `collect_at_bot_reply` | 被 @ 时是否也采集 | 与 `collect_skip_commands` 是「或」关系，都会拦掉这类消息 |
| `collect_sender_mode` | 发送者过滤模式：`blacklist`（默认）/ `whitelist` | 只作用于自动采集 |
| `collect_senders` | 过滤名单（用户 ID） | 白名单模式下**留空 = 谁都不采**（安全默认）；黑名单模式下留空 = 全部放行 |
| `skip_senders` | 兼容旧键，等价于往黑名单追加 | 仅在 `blacklist` 模式生效 |
| `collect_faces` | 只登记 QQ 表情 id | 与图片采集独立 |

### 静默相关（只影响「是否回话」）

| 配置 | 作用 |
| --- | --- |
| `silent_groups` | 显式静默群 |
| `auto_silent_in_collect_groups` | 偷图群自动静默 |
| `silent_scope` | `text_only` 只静默文本、图片照发；`all` 全静默 |

> 静默**不影响**图片存到哪个分类，也不影响权限判定——它只在输出前拦一层。

### 两个「未分类」的区别（最容易混淆）

| 配置 | 含义 |
| --- | --- |
| `collect_namespace` | **采集落点**：潜水偷来的图进哪个分类 |
| `default_namespace` | **迁移目标**：删除某个分类时，里面的图搬到哪个分类 |

两者默认值恰好都是 `未分类`，但语义完全不同。想把「偷来的」和「删分类回收的」分开，
把 `collect_namespace` 改成比如 `采集` 即可。

### 指令行为 vs 采集行为：两组开关正交

| 开关组 | 只管 | 不管 |
| --- | --- | --- |
| `auto_collect` + `collect_groups` + `collect_*` | **自动采集**：收哪些消息里的图、落哪个分类、按发送者过滤 | `/加图` 能不能用 |
| `open_groups` / `post_groups` / `default_group_mode` / `private_mode` | **谁能用指令**（`/加图` 是写操作） | 自动采集 |

采集的落点永远是 `collect_namespace`，与「谁有权限」无关；
`/加图` 的落点永远是用户写的那个分类名，与采集开关无关。

**唯一的联动（必读）**：`collect_groups` 经 `auto_silent_in_collect_groups`（默认开）
会让这些群自动静默 —— 于是 `/加图` 在里面**照常执行但不回话**。
不想要这个连带效应就把 `auto_silent_in_collect_groups` 关掉。
另外 `collect_groups` **留空**时不会判为偷图群，所以也不会有自动静默。

### 常见组合的实际效果

| 情形 | 配置 | 结果 |
| --- | --- | --- |
| 1 | 群同时在 `collect_groups` + `open_groups`，`auto_collect` 开，发送者白名单含某人 | 全员都能用 `/加图`（`open_groups` = 白名单群模式）；自动采集**只收名单内成员**发的图 |
| 2 | 群同时在 `collect_groups` + `open_groups`，`auto_collect` 关 | `/加图` 全员可用；**完全不采集**（但保留期清理照跑） |
| 3 | 群只在 `open_groups`，`collect_groups` 留空，`auto_collect` 开 | `/加图` 全员可用；图片**会被采集**——留空表示「所有群都采集」，含这个群；且不判偷图群，不会自动静默 |
| 4 | `collect_groups` 留空，`auto_collect` 开，其余默认 | 图片在**所有群**被采集；`/加图` 对**普通成员**不生效（`default_group_mode=none`），但**管理员始终可用** |

> 两个最容易踩的误解：
> ① `collect_groups` 留空是「**不限制**」而不是「不启用」——启用与否由 `auto_collect` 决定；
> ② 「`/加图` 不生效」通常是权限问题（受 `default_group_mode` 影响），与采集配置无关。

## /加图 支持引用（reply）消息 v1.4.0

手机上「图片 + 文字指令」常常发不出同一条消息，于是支持：**引用一条含图片的消息，再发 `/加图 分类名`**。

取图顺序：先用 AstrBot 已解析好的 `Reply.chain`；若为空，再尝试通过协议端
`get_msg`（`event.bot.call_action("get_msg", message_id=...)`）回拉被引用消息。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `allow_reply_collect` | `true` | 是否允许引用收录 |

**边界（有意为之）**：引用取图只在 `/加图` 指令路径生效，**被动采集不会回拉引用**。
否则任何一条群消息都能诱导机器人去取任意 `message_id`，把内容采集变成协议端取图接口。

**可靠性说明**：能否回拉取决于协议端实现与消息是否过期。拉不到时静默降级
（用户只会看到「未检测到可用图片」），不影响 `/加图` 主流程。`Reply` 没有 `message_id` 字段，
只有 `id` —— 实现用的是 `id`。

### 权限（与采集互不影响）

| 配置 | 作用 |
| --- | --- |
| `plugin_admins` | 全局管理员（整库） |
| `group_admins` | 群级管理员（只能管 `group_id == 本群` 的图） |
| `open_groups` / `post_groups` | 白名单群 / 发图群 |
| `default_group_mode` | 未配置群的模式，默认 `none`（仅管理员） |
| `private_mode` | 私聊模式，默认 `post` |

> 注意：默认 `none` 模式下，普通成员**不能用 `/加图`**——但被动采集照常工作。
> 「加图没反应」通常是被权限拦了（群里会收到提示），而不是采集没生效。

## 权限：群级三档模式

| 模式 | 加图 | 发图 | 管理 | 分类增删改 / 解屏 |
| --- | --- | --- | --- | --- |
| 白名单群 `open_groups` | 全员 | 全员 | 仅管理员¹ | 仅全局管理员 |
| 发图群 `post_groups` | 仅管理员 | 全员 | 仅管理员 | 仅全局管理员 |
| 未配置（`none`） | 仅管理员 | 仅管理员 | 仅管理员 | 仅全局管理员 |

¹ `whitelist_allow_manage` 可放开，默认关闭，且即使放开也只限本群采集的图。

## 存储

```
data/plugin_data/astrbot_plugin_image_pool/
├── pool/<分类名>/000001.png      # 图片二进制
├── index.sqlite3                 # images / categories / blocked_hashes
└── faces.jsonl                   # 可选：QQ 表情 id 登记
```

`seq` 即用户可见 id，**删除后不回收不重排**。`source` 区分 `manual`（人工 `/加图`）
与 `auto`（采集），保留期清理默认只动后者。

## 分类即 tag

- 分类 = tag，`UNIQUE(char_name, sha256)` 只在**分类内**生效 → 同一张图可挂在多个分类下。
- 移动 `move` = 换 tag（搬文件 + 删源行）；复制 `copy` = 加 tag（`copy2` + 源不动）。
- 因此「设了分类就移出原分类」是 move 的必然结果。

## WebUI 配置项长什么样

| schema 类型 | WebUI 控件 | 本插件里的例子 |
| --- | --- | --- |
| `bool` | 开关（switch） | 开启潜水采集、允许引用收录、偷图群自动静默 |
| `string` + `options` + `labels` | **下拉菜单**（显示 labels，存 options 的值） | 未配置群的模式、私聊模式、静默范围、多图发送方式、发送者过滤模式、清理范围 |
| `int` + `slider` | 滑块 + 数字输入（输入值会被钳制到区间内） | 单次出图上限、单条消息图片上限、/图库 列表条数、缩略图边长 |
| `int` / `float`（无 slider） | 数字输入 | 保留天数、容量上限、清理检查间隔 |
| `string`（无 options） | 单行文本框 | 采集落点分类、转发显示昵称、删分类的迁移目标 |
| `list` | chip 标签编辑器（一条一个） | 各类群号 / 用户 ID 名单 |

### 说明文字分两处写（这就是「文字被遮挡」的解法）

| 字段 | 渲染位置 | 用法 |
| --- | --- | --- |
| `description` | 左侧那一行的**短标题** | 本插件一律 ≤ 12 字；长了会自己换行，别往里塞长句 |
| `hint` | 标题**下方的说明行**（小字号灰色、自动换行） | 承载完整解释，多长都不挤 |
| `obvious_hint` | 说明行前加 ‼️ 强调 | 用在「配错就会静默失效」的项上 |

> 官方文档说 `hint` 是右侧问号的悬浮提示，但当前 master 的 `AstrBotConfig.vue`
> 实际把它渲染成标题下方的常显 subtitle，`obvious_hint` 只加一个 ‼️ 前缀。以源码为准。

下拉是**强约束**：以前这些项是单行文本框，写错一个字母会静默回落到默认值（比如把
`whitelist` 打成 `white-list` 就变成「仅管理员」）。改成下拉后这类错误不可能发生。

配置项与本代码的一致性有断言守着：每个下拉的 `options` 必须等于代码接受的值集合、
`labels` 与 `options` 数量对齐、默认值在选项内、滑块区间合法、`description` 不超过 12 字。

## 已知约束

- 分类名不区分大小写之外不做同义合并。
- QQ 表情只有 id、无图片本体；落地表情图需协议端提供按 id 取图接口。
- WebUI 管理页的权限 = Dashboard 登录账号（无 UID 映射，故不叠加 `plugin_admins`）。
- `forward` 依赖平台支持合并转发，不支持时请改用 `chain` 或 `separate`。
- 保留期清理是**惰性**触发（随消息按间隔检查），长时间无消息则不会清理；可 `/图库 清理` 手动补一次。
- `retention_source` 只认 `auto` / `all`；填其它值会被当作"配置非法"而**跳过本次清理**（宁可不清，也不误删人工收录的图）。
- 老库（≤ v1.5.0）里若同时存在"仅大小写不同"的两个分类，它们会共用同一个目录。启动日志会告警；解析时**精确名优先**，所以 `/HATSUNE` 一定落在 `HATSUNE` 上。这类分类的**删除/迁移会被拒绝**（会连带毁掉对方的文件），请先用 `/图库 别名 收编 <错名> <正式名>` 合并成一个分类。
  - 折叠冲突下，被占用的那一方会用带后缀的合成键占位（如 `hatsune#2`）。这个键理论上可被输入命中（`/hatsune#2` 会解析到该分类），但正常使用不会碰到，仅作为不变量兜底。
- 索引指向的文件被外部删除后，该行会保留（不会自动删记录、丢元数据）；**重新收录同一张图即可就地修复**。`/图库 列表` 的计数可能因此包含"文件已不在"的行。
- 分类名不能是内置指令名（`加图` / `图库` / `发图` …）：`/图库 新建`、`/加图 <新名>` 的自动建分类、WebUI 的重新分类都会被拒。
